## Observed coverage and limits

- Every SQL file parsed as an in-memory database; the catalog lists **every table, columns, and row count**. Tables without ownership columns remain cataloged but supply no direct subject link. Serialized JSON columns can carry identifiers and require the existing nested parser.
- All four supplied PDFs yielded text and at least one table; no source PDF required Vision. The scanned-page branch now renders a content-keyed PNG with `pypdfium2` and routes it through the same OCR/strict mini-Vision handler. A forced scanned-page test verifies the render and routing without modifying a source PDF.
- The external Tesseract executable is absent, but the repository-local RapidOCR CPU engine reads **11/11 available images**. High-detail `gpt-4o-mini` reads the full screenshot with a strict JSON Schema and a bounded retry. OCR and Vision are cross-checked by exact visible IDs; an OCR-empty image needs a second independent Vision agreement. Prompt, model, schema, detail and image-byte hash distinguish cached model responses.
- Filesystem `mtime` reflects the dataset copy date (2026-10-24), after audit timestamps. It is **not** evidence time and is not used for audit cutoff. EXIF, source timestamps and manifest capture times are the admissible signals.
- The five target resources in [the ownership audit](cases_01_02_03_04_31_audit.md) lack a same-row subject link. No status or step is synthesized from a mere shared file or matching numeric suffix.
- All 24 SQL exports were separately checked as 127 table instances; 716 exact-identity-linked rows, including historical email aliases, resolved to concrete systems and none to a generic `sql` system. Independent exact-column and nested-JSON passes find 186 and 530 owner-bearing rows respectively, with zero omissions in either group. See [schema_mapping_audit.md](schema_mapping_audit.md). Generic replica tables use each row's explicit `origin_system` plus nested `record_json` identifiers; `snapshot_scope` has no per-user owner.
- A separate traversal finds 544 direct owner/resource pairs in the 28 JSON files, and the production extractor recovers all 544. A separate structured-line scan finds 674 direct pairs in 26 logs and 39 in the plain-text handover, including exact historical email hashes; all are recovered. The logs include quoted key/value, JSONL, readback pipes, operations-stream pipes, syslog and cloud-runtime messages; ownership may cross lines only through an exact prior trace ID. See [json_owner_coverage.md](json_owner_coverage.md), [log_schema_coverage.md](log_schema_coverage.md), and [log_trace_integrity.md](log_trace_integrity.md).
- `subject_selector`, `lookup_value`, query-start messages, and free-text mentions are query context. They do not prove a stored record or owner. Post-audit observations are kept separate from audit-time state.
